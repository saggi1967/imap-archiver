# mailarc 2.1.0.0

Dieses Release bringt **zentrale, verschlüsselte IMAP-Zugangsdaten**: Der IMAP-Zugang
wird einmal interaktiv angelegt und liegt danach verschlüsselt im zentralen
Service — kein IMAP-Passwort muss mehr in der `.env` jeder einzelnen Installation
stehen.

## 🔐 Zentrale Konten statt Passwort je `.env`

Bei zentraler Speicherung (`STORAGE_BACKEND=rest`) legst du den Zugang einmal an:

```bash
mailarc account add        # fragt Host, Benutzer, Passwort (verdeckt), Ordner ab
mailarc account list       # alle Konten (ohne Passwort)
mailarc account remove <label>
```

Das Passwort geht an den mailarc-server und wird dort **Fernet-verschlüsselt**
gespeichert. In der `.env` dieses Clients genügt danach das Konto-Label:

```bash
STORAGE_BACKEND=rest
REST_BASE_URL=https://archiv.firma.example
REST_API_TOKEN=dein-token
ACCOUNT=firma-stephan
```

Host, Benutzer, Passwort und Ordnerliste kommen zur Laufzeit vom Server; die
lokalen `IMAP_*`-Felder werden dann ignoriert. Der Client verbindet sich weiter
selbst read-only zum IMAP — er holt die Zugangsdaten dafür nur kurz über HTTPS.

## 🧩 Serverseitig (mailarc-server 2.1.0.0)

- Neue `account`-Tabelle, `crypto`-Modul (Fernet) und `/accounts`-Endpunkte
  (Anlegen/Auflisten/Löschen + Token-geschütztes `…/credentials`).
- Braucht einen `SECRET_KEY` in der Server-`.env`:

  ```bash
  python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
  ```

- Die Tabelle wird beim Serverstart automatisch angelegt (`create_all`) — für
  bestehende DBs genügt ein Neustart. Docker-Image zieht `cryptography`, Compose
  reicht `SECRET_KEY` durch.

## 🛡️ Sicherheitshinweis

Die Verschlüsselung ist *Encryption at Rest*: Sie schützt DB-Dumps und Backups,
**nicht** einen kompromittierten Server — der braucht den Schlüssel zwangsläufig,
um den Clients wieder Klartext zu liefern. Deshalb:

- REST-Strecke über **HTTPS** betreiben (das Passwort reist beim Sync zum Client).
- `SECRET_KEY` getrennt von der DB sichern — geht er verloren, sind die
  gespeicherten IMAP-Passwörter unwiderruflich nicht mehr entschlüsselbar.
